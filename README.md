# 花火陪你玩

花火陪你玩让 Bot 与用户通过独立 WebUI 一起玩五子棋、中国象棋、围棋、井字棋、黑白棋、海龟汤、贪心骰子、你画我猜、二十一点和谁是卧底，同时保留 AstrBot 的正常聊天、人格、生活场景和长期记忆链路。

## 核心行为

- 用户通过 QQ 自然语言邀请 Bot 玩五子棋、中国象棋、围棋、井字棋、黑白棋、海龟汤、贪心骰子、你画我猜、二十一点或谁是卧底，由 LLM 工具创建房间；进入房间后的游戏切换和玩法选择都在 WebUI 对话区完成。
- 游戏操作和 Bot 对话都在 WebUI 完成；桌面端游戏区与对话区并列，手机端可切换“游戏 / 对话”视图。
- Bot 根据人格选择简单、普通或困难棋力；贪心骰子中对应稳健、均衡或大胆的风险倾向，玩家不能在网页直接选择。
- 五子棋、黑白棋、中国象棋与围棋是两人对弈：房间固定 2 个玩家席，一个人坐下后可以等另一位真人，也可以直接点「和花火对局」让花火坐到对面；两位真人到齐立即开局。棋类首局可选自己先手/花火先手/随机，象棋可选我执红/我执黑/随机；之后每局自动换先（棋类黑白互换、象棋红黑互换）。围棋首局同样可选我执黑/我执白/随机。
- 两位真人对局时每步默认 180 秒：轮到的一方超时未落子判负；掉线时棋盘先暂停等重连（默认 90 秒），回来即继续。和花火练习局不计时。两项时长可在配置中心调整，设为 0 关闭。
- 两位真人下棋时花火只做旁观解说，按昵称和执方称呼双方，不会把自己算成对局一方。解说的模型可以单独指定：在配置中心的「花火解说」里填 `commentary.provider_id`（可选 `commentary.model`），留空则跟随所在会话的聊天模型，设置对所有房间生效。
- 棋类对局中，对面是真人时不能中途退席；对面是花火时退出会先确认，确认后本局作废。花火坐着时，局间点「等对手来」可以请花火离座，把位置留给朋友。
- 象棋两人同房时 1 号位执红先走、2 号位执黑；单人练习局可选我执红、我执黑或随机。井字棋可选执 X、执 O 或随机；黑白棋黑方先行。
- 围棋采用中国规则数子（黑贴目可配），禁止自杀与全局同形；双方连续「停一手」后结算，终局前需把死子吃净。界面右侧实时显示黑白胜率、领先目差与提子数（面板默认收起成一行，点开才展开条形图），花火解说会引用这些数字。
- 两个人对弈时，棋盘上方会显示执黑与执白（象棋为红与黑）双方的头像和昵称，轮到谁那一侧会高亮。
- 黑白棋使用标准 8×8 规则：落子必须夹住并翻转对方棋子，合法位置会显示提示点；一方无合法落子时自动跳过，棋盘填满或双方都无合法步时按棋子数量结算。它和围棋共用右侧那块胜率面板，按子数差换算，剩余空格越多数值波动越大。
- 贪心骰子每局随机先手，双方选择继续掷或收手存分，率先达到 50 分获胜。
- 二十一点中 Bot 担任庄家：用户单独对庄，或开放 2-6 人后各自持一手牌轮流要牌、停牌，庄家再按规则补牌并统一结算。
- 谁是卧底中多人分平民、卧底与白板阵营，轮流描述各自的词条并公开投票淘汰出局者，卧底必须掩饰身份让自身与其接近的词条混迹在众人之中。
- Bot 操作有轻微延迟。五子棋、黑白棋与围棋搜索在线程中执行，象棋通过单独的 Pikafish 进程串行计算，井字棋和骰子策略在内存中完成，均不阻塞 AstrBot 事件循环。
- 用户在 WebUI 对话区自然提出“再来一局”时，Bot 直接在原房间重置当前游戏，保留链接、玩家身份、多人席位、访客序号和累计统计，不创建新房间；海龟汤会按当前玩法开始全新题目。
- 九种游戏分别累计统计。切换游戏保留房间链接、玩家、访客序号和权限；进行中的游戏必须明确确认放弃后才能切换。
- 棋类的悔棋以及通用的暂停、继续和认输/放弃都从 WebUI 对话区发起。QQ 只负责创建房间、接收链接和绑定一次性令牌；海龟汤和贪心骰子不支持悔棋。单人局（含和花火对弈的棋类）对局进行中退出对局会先二次确认，确认后本局作废、不计胜负；双人对弈与多人玩法在对局中不能中途退席。
- 普通走棋和掷骰不调用模型；Bot 出题海龟汤的问答仅调用隐藏裁判，玩家出题海龟汤只向模型提供公开线索与公开回合。房间结束时只为已绑定发言者保存有限对话摘录，不保存完整房间记录。
- 游戏中的 Bot 回复、系统事件和玩家消息只显示在当前房间 WebUI，不发送到 QQ，也不写入 AstrBot 的普通对话历史，避免临时游戏语气影响后续正常聊天。
- WebUI 对话会按当前房间和发言者注入实时游戏状态；匿名观众不读取或写入长期记忆。只有私聊来源且房内仅有一名已绑定访客时才读取该用户的私人陪伴记忆，避免公开回复泄露个人信息。
- 身份确认前不读取该用户的长期记忆或生活场景，也不写入共同经历。
- 普通房间的每位访客进入玩家席前，必须在 WebUI 查看一次性令牌，并在原群聊或私聊中直接发送令牌，或发送“绑定玩家 令牌”；令牌只绑定当前房间的一个访客，使用一次后失效。配置固定 HTTPS 域名并启用受信任浏览器后，用户可以选择让同一浏览器在后续新房间中自动确认 QQ 身份。
- 绑定成功后保存发送者当时的 QQ 昵称/群名片。页面和 Bot 优先显示昵称，同时保留访客序号用于重名区分、交换申请和管理操作；昵称不是权限凭据。
- 群聊中的普通聊天始终不注入房间状态。私聊单玩家场景默认临时注入只读游戏事实，让 Bot 能回答当前游戏、比分、执子和最近结果；不注入 WebUI 对话或控制能力，也不写入普通聊天历史。房间关闭后最近结果默认在内存中保留 30 分钟。
- 房间结束时按已绑定 QQ 分别保存游戏摘要和有限对话摘录，不保存逐步棋谱或完整房间聊天记录。
- AstrBot 或插件重载时销毁所有活动房间，不恢复未完成棋局。

## 房间权限

插件配置中的游戏管理员与 AstrBot 管理员相互独立。

- 群聊默认只允许游戏管理员创建房间。
- 群里建房还要求消息里真的提出了请求：点了具体玩法（五子棋 / 海龟汤……），或说了「来一局 / 陪我玩 / 打开房间 / 来个 / 开个」。只是被 @ 唤醒、随口闲聊时，即使模型想调建房工具也会被插件拒绝，不会往群里发链接；被拒绝后花火会先问一句，用户回「好 / 来吧」即可正常开局。私聊不设这道校验。
- 管理员创建的房间中，所有访客先进入观众席并获得稳定序号。管理员在“游戏管理台”选择一个或多个序号并分别绑定玩家 QQ 后才能开局；已在网页里带上身份（受信任浏览器 / 已绑定 QQ）的访客可以直接自己入座，不需要再手动安排。
- 普通房间中，只有完成 QQ 令牌绑定的访客才能自行加入玩家席；海龟汤、二十一点、谁是卧底与两人对弈的五子棋/黑白棋允许已绑定访客加入空余玩家席。创建者不再默认占据首个玩家席。
- 私聊房间采用普通房间规则。
- 管理台展示创建者、访客序号、席位和房间状态，不展示棋盘、棋谱或进行中的海龟汤汤底。管理员可以切换房间游戏与棋力，但不能改题目。
- 「全部房间」右上角可以手动开房：选好玩法点「开新房间」，插件会直接建一个管理员房间并把访问网址复制到剪贴板；每行房间也有单独复制链接的按钮。这类房间没有 QQ 会话：带身份的访客可自己入座，匿名访客由管理员在管理台「安排玩家」补身份。

## QQ 游戏菜单

在 QQ 中发送 `/game 游戏菜单` 可以查看插件当前支持的全部游戏，以及所有群聊合计、所有私聊合计的活动房间数量与配置上限。若 AstrBot 使用了不同命令前缀，请将 `/` 替换为对应前缀。

## 在群里玩海龟汤

房间开出来之后，群里可以直接用指令参与，和网页端是同一局、同一套规则：

| 指令 | 作用 |
| --- | --- |
| `汤 开局 [简单/普通/困难]` | 直接在群里开一局，自动把发起人排进玩家席并发出房间链接 |
| `汤 提问 是不是和灯塔有关` | 问一个是/否问题 |
| `汤 推理 他是灯塔管理员…` | 提交对汤底的完整推理 |
| `汤 提示` | 要一条提示（消耗一次机会） |
| `汤 揭晓` / `汤 附议` / `汤 反对` | 发起或参与揭晓表决 |
| `汤 状态` / `汤 查看` / `汤 帮助` | 看进度、看最近问答、看帮助 |
| `汤 复盘` | 本局回顾：结束后给汤面 + 汤底 + 关键问答；进行中只给进度、不剧透 |

也支持 `汤提问`（不带空格）、`海龟汤 提问`、`/汤 提问` 等写法；群里说「汤圆好吃」不会被当成指令。群里发的问答会同步显示在网页聊天窗，并带 `QQ` 角标。

反过来也同步：**网页里问的题、交的推理会汇总发到群里**，但不会一条一条刷屏——攒 12 秒后合并，最多 4 行，多的写「还有 N 条」。条数少时优先发一张 t2i 渲染的「问答速报」卡片（暖棕小报样式，带玩家号、提问、判定色块），条数多时优先发 QQ 合并聊天记录（可展开看完整流水），两种互为兜底，都失败才退回纯文本。不想要可关掉 `turtle_soup.qq_sync_questions`。

更方便的是**不用写指令**：直接 `@花火 是不是和灯塔有关？` 就是一次提问，`@花火 他是灯塔管理员，灯灭了导致沉船` 这种一整段陈述会当作推理提交。判定看句式——带问号或「吗 / 是不是 / 为什么」算提问，够长的陈述句算推理；拿不准时按提问处理（多问一句只浪费一轮，推理判错可能直接把汤底揭晓）。寒暄（「谢谢花火」「在吗」）不会被当提问。不想用这个入口可以关掉 `turtle_soup.qq_at_question`。

这个 @ 入口**只在游戏进行中生效**：房间还没开局、已经结束、或停在「再来一局」确认里时，@ 花火只是普通聊天，不会凭空多出一条提问。

海龟汤默认**不排轮次**：玩家席上谁想到就问，不用等「轮到你」。人一多，按顺位轮转是最劝退的设计——二十个人一轮就是二十次提问。想回到严格轮次就把 `turtle_soup.free_questioning` 关掉（关掉后按席位顺位轮流，并启用回合超时自动换人）。严格轮次下每次换人会在群里播报「轮到 @某某 提问」，绑了 QQ 的会被真的 @ 到，没绑的显示座位号——群里的人不用猜现在该谁（`turtle_soup.qq_turn_announce` 可关）。每局提问默认上限 15 次（`turtle_soup.max_questions`，填 0 表示不限）：到上限后**只停提问，推理还能继续交**，否则这局就永远解不开了。推理另有一份额度 `turtle_soup.max_answers`（默认 8 次，**整局共享**，不是每人一份）：额度用完那一次还是没人答对，就直接揭晓汤底并结算，不用干等到 30 分钟超时。群里和网页都会显示「推理剩 N」。

每条回答后面都会带上进度：群里是「（已问 12/15 · 提示剩 2 · 推理剩 5）」，网页在轮次那一行显示同样的数字，两边永远一致。这个数字**只算玩家问的**——花火的自动提问不占玩家的额度，否则人少的房间里，一半额度都被花火问掉了。

还没坐进玩家席的人 @ 花火提问时，插件会自动给他安排一个空位（网页端会显示「从群里自动加入玩家席」），不需要先跑去网页拿令牌。海龟汤默认不限人数，群里人多也坐得下；想限制就把 `turtle_soup.max_players` 填成正数。自动入座可用 `turtle_soup.qq_auto_bind` 关掉。

人多时模型容易限流，插件做了三层兜底：**并发闸门**（同时最多 3 个判定在跑，多出来的排队）、**排队超时**（等 25 秒还没轮到就直说「问的人有点多」，而不是让玩家等满 30 秒的模型超时）、**限流退避重试**（识别到 429 / overloaded 时等 0.8 秒、2 秒各重试一次）。判定失败不会消耗提问或推理额度——额度是在结果落库那一步才记的。

判定跑偏也有兜底：推理型模型偶尔不按格式输出 JSON，而是把「让我想想……」整段思考过程吐出来。以前解析不到 JSON 就静默当成「无关」，玩家问在点上却被告知问错了。现在会**重试一次**（追加「只输出一行 JSON」的硬约束），两次都不行就回「花火这次没判断出来，这句话不算次数」，不落库、不扣额度。

使用前提是 QQ 已绑定到玩家席：在网页里取一次性令牌，然后在群里发 `绑定玩家 令牌`。没绑定时指令会直接给出这条引导。群里发言也会刷新你的活跃时间，不会因为「按在线人数」的节奏被算成缺席。

## 海龟汤题库

插件自带 226 道海龟汤（`soup_library.json`），出题顺序是：自定义投稿 → 内置题库 / 网络题库（顺序由 `turtle_soup.library_priority` 决定）→ LLM 现编 → 内置兜底 12 条。默认「优先内置题库」，它不联网、出得快；想要更新鲜的题就切到「优先网络题库」，拉取失败会自动换下一种来源。

内置题库只存汤面与汤底，第一次抽到某道题时会用模型补出标题、关键事实、渐进提示、题材与诡计，结果缓存在数据目录的 `soup_library_cache.json`（不改动题库文件）；模型不可用时退回规则版字段，保证照样能开局。题目按内容等级分档，`all_ages` 57 道、`normal` 140 道、`unrestricted` 29 道，受 `turtle_soup.content_level` 控制。

题库内容来自 [`IPF-Sinon/astrbot_plugin_soupai`](https://github.com/IPF-Sinon/astrbot_plugin_soupai)（AGPL-3.0），仅收录汤面与汤底。不想要可直接关闭 `turtle_soup.library_enabled`。

### 难度档位

难度不再只是一个标签，它决定这一局能问几次、能要几次提示、能猜几次，以及「猜中」的门槛：

| 难度 | 提问限制 | 提示次数 | 推理次数 | 猜中条件 |
| --- | --- | --- | --- | --- |
| 娱乐 | 不限 | 15 次 | 不限 | 完全还原 / 核心推理正确 / 部分正确 |
| 简单 | 90 次 | 10 次 | 8 次 | 完全还原 / 核心推理正确 |
| 普通 | 35 次 | 5 次 | 4 次 | 完全还原 / 核心推理正确 |
| 困难 | 15 次 | 1 次 | 2 次 | 仅完全还原 |

提问与推理都是**整局共享**，不是每人一份；提示按顺序发放，不同玩家拿到的不会重复。开局时可以在群里写 `汤 开局 困难`，或在网页里切换难度（详见房间界面的难度按钮）。不想按难度表走，就把 `turtle_soup.follow_difficulty` 关掉，改用 `max_questions` / `max_hints` / `max_answers` 三个自定义数值。

### 投稿自己的题（仅私聊）

私聊机器人发送：

| 指令 | 作用 |
| --- | --- |
| `添加海龟汤 汤面\|汤底` | 收录一道题（汤面至少 20 字、汤底至少 30 字），等级默认「普通」 |
| `添加海龟汤 全年龄 汤面\|汤底` | 指定内容等级：`全年龄` / `普通` / `不限制`（也认 `成人`、`重口`、`[全年龄]` 写法） |
| `我的海龟汤` | 看自己投过哪些题（带等级标签） |
| `删除海龟汤 2` | 按序号删掉一道 |

投稿存在插件数据目录的 `turtle_soup_custom.json`，**出题优先级最高**——排在内置题库和模型现编之前，投了就会真的被玩到。这些指令只在私聊生效：群里发汤面等于当众剧透，而且很容易被刷掉。管理台「题库管理」页可以直接删投稿。

内容等级决定这道题会出现在哪种房间：房间的内容等级（`turtle_soup.content_level`）是「全年龄」时，只抽 `全年龄` 的题；标成「不限制」的题只在同样放开到「不限制」的房间里出现。汤面本身以「普通」开头的句子不会被误认成等级——后面必须跟空格或冒号才算。

题库是大家共用的：「我的海龟汤」只列你自己投的，`删除海龟汤 序号` 也只能删自己的（序号按全库算，看到的就是能删的）。别人投的题你抽得到、但删不掉。

### 管理台「题库管理」

AstrBot 插件拓展页 → 游戏管理台 → 题库管理：可以看到内置题量与等级分布、已经出过多少题（按来源拆分）、模型补全缓存条数、玩家投稿列表；支持「重置出题记录」（让所有题重新参与抽题，不动题库文件）和删除单条投稿。

## 受信任浏览器

受信任浏览器默认关闭，只在 `server.public_base_url` 配置了固定 HTTPS 地址且 `identity.enable_trusted_browser` 开启时生效。Cloudflare Quick Tunnel 等临时域名不会启用长期 Cookie，仍按每个房间的一次性 QQ 令牌流程工作。

用户首次完成 QQ 令牌绑定时，可以在 WebUI 取消“在此浏览器记住我的身份”。选择记住后，服务端生成高强度随机设备凭证；浏览器只通过 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie 保存原始凭证，插件数据目录中的 `trusted_browsers.json` 只保存 SHA-256 摘要、QQ、昵称和有效期。

设备凭证默认有效 30 天，可配置为 1-365 天，每个 QQ 最多保留 8 台设备。受信任浏览器进入新房间后只自动确认 QQ 身份，仍停留在观众席，需要用户主动加入对局；活动房间、棋局和对话依旧不会跨插件重载恢复。

WebUI 的身份区域可以取消当前浏览器信任；在 QQ 中发送 `/game 撤销网页绑定` 可以撤销该 QQ 的全部设备。撤销不会中断当前房间，但之后进入新房间需要重新使用一次性令牌。

## 陪伴联动

安装支持游戏事件扩展 API 的“我会永远陪着你”后，可以分别开启游戏情绪余韵和主动邀请。两项默认关闭；陪伴插件缺失、尚未加载或版本较旧时只跳过联动，不影响创建房间和进行游戏。

情绪余韵在每局结束后立即按实际玩家分别结算。事件只包含游戏、胜负、累计比分、难度和房间来源等结构化信息，不包含棋谱、隐藏汤底或其他玩家的对话。仅绑定后真正进入过玩家席的用户收到胜负余韵；匿名用户和仅旁观者不会参与结算。长期共同经历仍在房间销毁时按原规则汇总。

胜负余韵与陪伴插件已有的“受伤/拒绝”状态相互独立。陪伴人格可以很在乎输赢，也可以更在乎共同参与；连续胜负会累积，但竞争情绪和陪伴温度各自拥有由人格判断的上限与持续时间。WebUI 中提出“再来一局”时，陪伴插件会结合实际用语决定清除、缩短、保留或延长当前余韵。

主动邀请复用陪伴插件的主动消息链，不由游戏插件自行定时发送。开启后只注册一个候选能力，最终是否邀请仍受人格、日程、关系、免打扰、每日主动额度和冷却控制。邀请本身不会提前创建房间；用户明确接受后，仍由正常 QQ 对话中的游戏工具创建并发送链接。

## 贪心骰子

贪心骰子使用一颗六面骰。当前行动方掷出 2-6 时点数累加到本回合暂存分，可以继续掷或选择收手；收手会将暂存分加入总分并换人。掷出 1 时本回合暂存分全部丢失并立即换人，率先达到或超过 50 分的一方获胜。

每局先手由服务端随机决定。Bot 的稳健、均衡或大胆倾向由人格选择，但实际收手阈值还会根据领先或落后幅度、双方距离 50 分的距离动态调整。普通掷骰和决策不调用模型，仅在连续冒险、高分爆掉、大额存分及终局等节点触发人格化表达。

骰子点数使用服务端安全随机源生成，WebUI 只提交继续掷或收手操作，无法提交指定点数。Bot 每次掷骰会逐次公开并带轻微间隔，不会一次跳到最终结果。

## 海龟汤

海龟汤支持两种通过 WebUI 对话自然切换的玩法，页面不提供固定玩法选择按钮。两种玩法默认不限制玩家席人数（`turtle_soup.max_players` 填正数才封顶），也默认不排轮次：玩家席上谁都能随时提问，不用等顺位；关掉 `turtle_soup.free_questioning` 才回到「按稳定访客序号轮流 + 每回合默认 60 秒超时换人」。模型出题或判断期间暂停倒计时。多人房第一个玩家入座后不会立刻开局，而是停在准备状态，等大家坐好再由房内玩家点「开始出题」；**单人房也一样**——入座后先停一下，你才有机会先点「我来出题」（不然一入座花火就开始生成题目，这个按钮永远点不到）。私聊里开好房把链接发到群里是常见玩法，停在准备状态也让大家来得及坐进来。开题之后仍然可以加入，不用重新开房。

“Bot 出题、玩家猜”沿用实时生成流程。玩家入席并开始后，Bot 输出结构化汤面、固定汤底、关键事实和渐进提示，再进行一次隐藏的自洽性校验。最多尝试三次，模型不可用或题目连续未通过校验时使用插件内置安全题。每次提问、完整猜测或提示申请都会消耗当前玩家的一回合。

对局开始后汤底保持冻结。当前玩家可以在 WebUI 对话区提出单个是非问题，公开裁决限定为“是、否、无关、部分正确”；复合问题会要求拆分。玩家也可以在对话区申请提示或提交完整推理，只有核心因果链和大部分关键事实命中才算成功解谜。放弃后会揭晓汤底，海龟汤不提供悔棋。多人局点「揭晓汤底」只是发起表决：发起后回合不变、可以继续提问，任一在席玩家都能附议，过半同意才真正揭晓；投票不受轮次限制。提示按「本局总量」计算（`turtle_soup.max_hints`），不是每人各一份：整局最多给这么多次，而且按题目里的提示顺序发放，不同玩家申请到的一定不是同一条；次数用完或提示库发完都会明确拒绝。

默认由花火出题。想自己出题时，在席玩家可以在房间页点「我来出题」，填标题、汤面、汤底（可选 3 条提示）后立即开局：**其他玩家和花火一起猜**，出题人不参与提问轮转，只负责裁决——问题按「是 / 否 / 无关 / 部分正确」回答，推理按「猜对了 / 不对」判定。花火作为普通参与者一起猜（配置 `turtle_soup.bot_join_player_host` 可关）：节奏按在线玩家数自动换算——N 个玩家各问一次，才轮到它问一次，人越多它越不抢话；每轮自己决定提问还是推理，但公开问答不足 3 条时只提问。它看不到汤底，只能读汤面与已公开问答。谁先被出题人认可就算谁赢（花火猜中记为花火胜），出题人也可以一键揭晓。申请出题期间，「再来一局」会被拒绝并说明原因——避免收拾好的题又被花火的一局顶掉。

“玩家出题、Bot 猜”不要求玩家上传隐藏汤底。当前玩家在 WebUI 对话区提供第一条公开线索，之后轮流回答 Bot 的问题或补充线索；Bot 每回合只根据全部公开内容继续提问或提交完整猜测。Bot 猜中后由当前玩家在 WebUI 确认，避免模型提前接触答案，也避免用不可靠的字符串匹配判定胜负。

多人模式下，观众可以向指定玩家发送交换申请；同一观众默认 30 秒只能申请一次，一次只能有一条待处理申请，申请 20 秒后失效。目标玩家接受后双方原子交换位置，新玩家不会继承原玩家绑定的 QQ 身份；若交换当前回合席位，新玩家获得完整回合时间。

房间页右侧的「换游戏」面板可以发起**投票换玩法**：选一款管理员已开放、且不是当前玩法的游戏，在线访客一人一票（发起即赞成），达到门槛后立即切换，房间链接与座位保持不变。门槛按发起时的在线人数锁定——只有自己在线时发起即通过，两人及以上时需过半且至少 2 票；反对票只做展示，不参与分母。默认只能在等人、开局前、局间发起，同一房间两次发起间隔默认 30 秒。要允许对局进行中也发起（通过即放弃当前局、本局不计战绩），需开启 `多人游戏 → 允许对局进行中投票换游戏`。

房间销毁时，共同经历和有限对话摘录会分别写给所有已绑定玩家，以及发言过的已绑定观众；匿名观众不会生成记忆。

进行中的公开房间快照只包含标题、汤面、已公开问答和提示，不包含汤底或关键事实。题目生成不读取用户长期记忆或生活场景，避免私人信息进入观众可见的汤面；房间结束时不会保存隐藏汤底。

结算面板提供「✨ 花火复盘」「分享战报」「📢 通知到群」。分享战报是浏览器 canvas 画的深棕「汤屋」长图，服务端播报需要图片时用 t2i（回退 Pillow）画同款海报，两者都不画汤底，只给汤面、参与玩家、统计与提问摘录（花火是主持人，不进玩家名单）。想调版式可直接在聊天里发顶层指令「海龟汤战报」（文案 + 复盘 + 海报）或「海龟汤海报」（只出图），加参数「未解开」可看无人解开的版本；这两条指令用的是完整示例数据（含汤底与 5 条提问），汤底只出现在聊天文字里并标注「仅测试」。

## 谁是卧底

谁是卧底是多人社交推理玩法。对局开始前按参与人数与配置的阵营比例分配平民、卧底与白板身份：平民与卧底各自拿到一对相近但不同的词条，白板玩家没有具体词条。所有玩家轮流描述自己的词条，发言中直接说出词条会被以 `***` 打码拦截；每轮公开投票淘汰得票最多的人，卧底需要掩饰身份，平民则要找出与大家不一样的卧底。游戏按经典规则由服务端结算四类胜负。

- 每局支持最多 10 个玩家席、最少 2 人即可开局（1 平民 + 1 卧底）；开启 AI 补位后可填充真实人数不足的空缺席位。
- 发言阶段默认每人 160 秒、投票阶段默认 120 秒；首轮存活人数不超过配置阈值时第一轮只发言、不投票，平票进入 PK 环节。
- 房主为第一位完成 QQ 身份确认的真实玩家，可在 WebUI 直接调整平民/卧底/白板比例，或由管理员在游戏管理台统一配置。
- 词条使用 JSON 持久化词库（`undercover_words.json`），预置 31 组种子词条；可在游戏管理台新增、删除、多行批量导入，或调用 LLM 批量生成并自动去重。
- 也支持私聊指令批量录入：游戏管理员（配置项 `rooms.game_admin_qq_ids`）私聊发送「新增词条 / 添加词条」，按提示把「词条1 词条2」每行一组发来即可入库，发「取消」退出（10 分钟内有效）。
- 发言相似度按所有玩家、所有轮次全局比对；与已有发言相似度超过阈值时会被驳回并提示换说法。

## 中国象棋引擎

中国象棋使用 [Pikafish](https://github.com/official-pikafish/Pikafish) 提供合法着法校验、终局判断和 Bot 走棋。插件不会导入第三方象棋规则 Python 库；Pikafish 作为独立进程运行。引擎不可用时只影响象棋，五子棋仍可正常创建和游玩。

默认允许管理员从游戏管理台按需安装，但不会自动下载。安装流程会：

1. 从 Pikafish 官方 GitHub Releases 读取最新发行版。
2. 下载 `.7z` 资产并校验 GitHub 提供的 SHA-256。
3. 只提取当前平台需要的可执行文件、`pikafish.nnue` 和许可证文件。
4. 在插件数据目录中原子替换托管版本，并执行 UCI 启动检查。

下载最多允许 160 MiB。可通过 `xiangqi.download_proxy` 显式设置 HTTP 代理；留空时继承进程的 `HTTPS_PROXY` 或 `HTTP_PROXY`。也可以设置 `xiangqi.engine_path` 使用自行安装的二进制，此时 `pikafish.nnue` 必须位于可执行文件同目录。

自动安装支持 Linux x86_64、Windows x86_64 和 macOS Apple Silicon；其他平台可以配置兼容的自备引擎。Pikafish 使用 GPL-3.0，NNUE 文件具有单独许可；官方许可证会随托管安装保存在插件数据目录。插件通过 `py7zr` 解压官方发行包。

象棋服务端以 Pikafish 返回的合法着法为准，采用 ICCS 坐标保存内存棋谱。无合法着法的一方判负；三次重复局面或连续 120 个半回合无吃子时判和。房间销毁或插件重载后不保存棋谱。

## 外部访问

房间服务默认按需监听 `127.0.0.1:6331`。如果端口已被占用，只会尝试后续十个端口，不会关闭或复用其他服务。

可按实际网络环境选择：

1. 在 `server.public_base_url` 配置现有 HTTPS 反向代理地址。
2. 在 `server.external_base_url` 配置 FRP、ngrok、Tailscale Funnel 或其他反向代理地址。
3. 安装 `cloudflared`，保留 `server.auto_quick_tunnel=true`，创建首个房间时按需生成 `trycloudflare.com` 临时 HTTPS 地址。

插件不会修改防火墙、执行 UPnP 或退回到公开服务器 IP。cloudflared 可以在配置中填写 `server.cloudflared_path`，也可以在游戏管理台通过代理下载到插件数据目录。

Quick Tunnel 首次启动后会先连续检查公网健康状态，确认临时域名已经生效才签发房间链接；随后保持到插件卸载或管理员在管理台手动停止，房间超时销毁不会让旧链接直接变成 Cloudflare 1033。已销毁房间的关闭原因只在内存中短期保留，旧链接会显示房间已经结束或过期。存在活动房间时如果 `cloudflared` 意外退出或临时域名连续失去连通性，插件会按间隔自动重建通道，并在原 QQ 会话发送新链接；临时域名发生变化后，旧消息中的链接无法继续使用。

反向代理需要将完整 HTTP 路径转发至实际监听端口。固定外部地址必须使用 HTTPS。

| 海龟汤每局推理上限 | 8 | `turtle_soup.max_answers`，`0` 为无限制；整局共享，用完仍没人答对就揭晓汤底；只在关闭「按难度自动决定次数」时生效 |
| 题库优先级 | 优先内置 | `turtle_soup.library_priority`：优先内置题库 / 优先网络题库 |
| 群聊互通总开关 | 开启 | `turtle_soup.qq_bridge_enabled`；关掉后指令、@ 入口、模型工具全部停用 |
| 网页问答同步到群 | 开启 | `turtle_soup.qq_sync_questions`；攒批合并成一条（优先速报图 / 合并聊天记录） |
| 轮次换人播报 | 开启 | `turtle_soup.qq_turn_announce`；仅严格轮次生效，换人时群里 @ 下一位 |
| 多人回合时间 | 60 秒 | `0` 关闭倒计时 |
| 交换申请冷却 | 30 秒 | `0` 不限制发送频率 |
| 交换申请有效期 | 20 秒 | 过期自动清理 |
| 开放投票换游戏 | 开启 | 关闭后房间页不显示「换游戏」面板 |
| 投票换游戏有效期 | 60 秒 | 超时未达门槛自动作废 |
| 投票换游戏冷却 | 30 秒 | 同一房间两次发起的间隔，`0` 不限制 |
| 允许对局进行中投票换游戏 | 关闭 | 开启后投票通过会放弃当前局（本局不计战绩） |
| 二十一点最大玩家席 | 1 人 | 默认用户单独对庄，可调为 2-6 人 |
| 贪心骰子目标分数 | 50 分 | 范围 20-200，新一局生效 |
| 私聊中提供游戏事实 | 开启 | 只读事实，不包含 WebUI 对话；群聊始终隔离 |

| 陪伴主动邀请游戏 | 关闭 | 邀请不会自动创建房间 |

页面刷新、观众进出和状态轮询不算有效操作。

本局结束后，玩家关闭页面会发送离开通知；若 8 秒内没有重新进入，房间会提前销毁并释放名额（「玩家席无人自动销毁秒数」设为 0 时不再做这项快速回收，改由「无有效操作超时」兜底）。刷新或短暂页面切换可以在宽限期内恢复。浏览器未能发送离开通知时，玩家心跳中断 60 秒后兜底销毁。进行中或暂停中的棋局不使用这项快速销毁，仍按“无有效操作超时”处理。
